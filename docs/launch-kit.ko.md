# K-Humanizer Launch Kit

이 문서는 K-Humanizer를 소개할 때 메시지와 근거를 일관되게 유지하기 위한
공유용 초안입니다. 실제 게시 전에는 최신 검증 결과와 링크를 확인합니다.

## 한 줄 포지셔닝

K-Humanizer는 실제 경험, 수치, 직무 용어는 지키면서 한국어 이력서의 번역투와
과장된 AI 표현만 걷어내는 오픈소스 Agent Skill입니다.

## GitHub 메타데이터

설명:

```text
사실과 직무 용어를 지키면서 한국어 이력서와 경력 문서의 AI투를 다듬는 Agent Skill
```

토픽:

```text
agent-skills, career, humanizer, korean, resume, writing
```

기본 CTA:

```bash
npx skills add evergreentree97/K-Humanizer --skill k-humanizer --full-depth
```

## 반드시 유지할 메시지

- AI 탐지기 우회를 보장하지 않는다.
- 실제 경험, 수치, 담당 범위와 완료 상태를 바꾸지 않는다.
- 이력서와 경력 문서를 첫 진입점으로 삼는다.
- 다른 문서, 메일, 메신저와 제품 문구는 확장 활용 사례로 소개한다.
- 200개 골든셋은 합성하고 익명화한 예시다.
- 데이터셋 무결성 통과와 실제 출력 품질 평가는 구분한다.

## Before/After 카드 원고

### 1. 운영

Before:

> 고객 문의 분류 체계 고도화를 통해 주간 평균 처리 시간을 18시간에서 11시간으로 크게 개선했습니다.

After:

> 고객 문의 분류 기준을 정리해 주간 평균 처리 시간을 18시간에서 11시간으로 줄였습니다.

핵심: 행동과 수치는 남기고 `고도화`, `크게 개선` 같은 부풀린 표현을 뺀다.

### 2. 기획

Before:

> 사용자 니즈 분석을 통해 서비스 개선 방향성을 수립하고 다양한 기능 기획에 기여했습니다.

After:

> 사용자 요구를 분석해 서비스 개선안을 정리하고 기능 기획에 참여했습니다.

핵심: 확인되지 않은 기능 수나 성과를 만들지 않는다.

### 3. QA

Before:

> 다양한 테스트 케이스를 수행해 서비스 품질 강화에 기여했습니다.

After:

> 테스트 케이스를 수행해 서비스 품질을 확인했습니다.

핵심: 발견한 결함이나 출시 효과가 원문에 없으면 추가하지 않는다.

### 4. 디자인

Before:

> 감각적이고 트렌디한 UI를 설계해 사용자 경험을 크게 개선했습니다.

After:

> 사용자 경험 개선을 목표로 UI를 설계했습니다.

핵심: 검증 근거가 없는 사용성 개선을 완료된 성과로 말하지 않는다.

### 5. 마케팅

Before:

> 바이럴 콘텐츠를 제작해 브랜드 인지도를 강화하고 의미 있는 성과를 창출했습니다.

After:

> 브랜드 인지도를 높이기 위한 콘텐츠를 제작했습니다.

핵심: 조회 수나 인지도 측정값이 없으면 바이럴 성과를 주장하지 않는다.

### 6. 완료 상태 보호

Before:

> 멤버십 등급 개편안을 제안해 경영 회의에서 승인받았지만 개발과 출시는 시작되지 않았습니다.

After:

> 멤버십 등급 개편안을 제안해 경영 회의 승인을 받았습니다. 개발과 출시는 시작되지 않았습니다.

핵심: 제안, 승인, 개발과 출시를 서로 다른 상태로 유지한다.

## LinkedIn 게시물 초안

```text
AI로 이력서를 쓰면 경력보다 AI가 먼저 보일 때가 있습니다.

문제는 `~를 통해` 같은 표현 하나가 아닙니다.

팀 성과가 개인 성과로 바뀌거나,
제안한 일이 출시한 일처럼 보이거나,
근거 없는 `크게 개선했습니다`가 붙는 순간 이력서의 신뢰도가 떨어집니다.

그래서 K-Humanizer를 만들었습니다.

실제 경험, 수치, 담당 범위와 직무 용어는 지키고
번역투와 과장된 AI 표현만 필요한 만큼 고치는 Agent Skill입니다.

운영, 기획, QA, 디자인 등 직무별 이력서 사례를 포함해
합성하고 익명화한 200개 골든셋도 함께 공개했습니다.

AI 탐지기 우회가 목표가 아닙니다.
읽는 사람이 믿을 수 있는 한국어가 목표입니다.

설치와 예시는 GitHub에서 확인할 수 있습니다.
https://github.com/evergreentree97/K-Humanizer
```

민감한 내용은 모두 가린 합성 문장 한두 개로 테스트해보고, 1) 더 자연스러운지 2) 의미나 담당 범위가 달라졌는지 3) 그대로 쓸 수 있는지만 알려주실 수 있을까요?
